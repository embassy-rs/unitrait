# unitrait

Traits with a single global implementation, resolved at link time.

A "unitrait" is a trait that has exactly one implementation across the whole
crate tree. It can be called from anywhere in the tree without carrying
generic parameters or instances around, without `dyn`, and produces link-time
errors if there is no implementation or more than one.

This is achieved by dispatching calls through `extern "Rust"` functions: the
defining crate declares (and calls) functions by symbol name, and the
implementing crate exports them. The linker matches them up.

The use case is allowing pluggalbe "drivers" for foundational, process-wide facilities
where generics would be too viral and `dyn` too costly. For example, it's used for the
`embassy-time` driver and the `embassy-executor` pender and trace hooks.

## How it works

### 1. Define the trait

Use the `unitrait::unitrait!` macro instead of a normal `trait`:

```rust
unitrait::unitrait! {
    /// AES-128 block cipher in ECB mode.
    pub trait Aes128Ecb {
        /// Opaque storage for the implementation's key schedule.
        /// The macro generates a struct with this size and alignment.
        #[opaque(size = 32, align = 16)]
        #[symbol = "_emb_crypto_aes128ecb_context"]
        pub type Context;

        /// Initialize with a 128-bit key.
        #[symbol = "_emb_crypto_aes128ecb_init"]
        pub fn aes128ecb_init(key: &[u8; 16]) -> Self::Context;

        /// Encrypt 16-byte blocks in-place.
        #[symbol = "_emb_crypto_aes128ecb_encrypt_block"]
        pub fn aes128ecb_encrypt_block(ctx: &Self::Context, blocks: &mut [[u8; 16]]);
    }

    /// This macro is generated by `unitrait!` and must be invoked in the driver crate.
    macro embassy_crypto_aes128ecb_impl(path = $crate);
}
```

The `unitrait!` macro does three things:

1. **Defines the trait** with `#[export_name]` attributes on every method, using the
   `#[symbol]` value. This makes each method a globally visible `extern "Rust"` symbol.

2. **Generates a helper macro** (`embassy_crypto_aes128ecb_impl!` in the example) that
   the driver crate invokes to emit:
   - `extern "Rust"` forward declarations for each symbol.
   - Thin wrapper functions that call those symbols.
   - A blanket `impl Trait for Type` that delegates to the wrappers.

3. **Generates an opaque `Context` type** when `#[opaque(size = N, align = M)]` is used.
   The generated struct is a byte array with the specified size and alignment, wrapped
   in `UnsafeCell` so it can be passed by mutable reference even when the trait method
   takes `&mut Self::Context`.

### 2. Implement the trait (driver crate)

In your HAL/driver crate, implement the trait normally, then invoke the generated macro:

```rust
// In embassy-stm32/src/aes/driver.rs
struct AesDriver;

impl embassy_crypto_driver::Aes128Ecb for AesDriver {
    type Context = [u8; 16];

    fn aes128ecb_init(key: &[u8; 16]) -> Self::Context {
        *key
    }

    fn aes128ecb_encrypt_block(ctx: &Self::Context, blocks: &mut [[u8; 16]]) {
        // ... hardware-specific code ...
    }
}

// At the bottom of the file, invoke the generated macro.
// This emits the `extern "Rust"` declarations and wrapper functions.
embassy_crypto_driver::embassy_crypto_aes128ecb_impl!(AesDriver);
```

The `impl!(Type)` macro expands to approximately:

```rust
#[allow(improper_ctypes)]
extern "Rust" {
    fn _emb_crypto_aes128ecb_init(key: &[u8; 16]) -> <AesDriver as Aes128Ecb>::Context;
    fn _emb_crypto_aes128ecb_encrypt_block(
        ctx: &<AesDriver as Aes128Ecb>::Context,
        blocks: &mut [[u8; 16]],
    );
}

fn aes128ecb_init(key: &[u8; 16]) -> <AesDriver as Aes128Ecb>::Context {
    unsafe { _emb_crypto_aes128ecb_init(key) }
}

fn aes128ecb_encrypt_block(
    ctx: &<AesDriver as Aes128Ecb>::Context,
    blocks: &mut [[u8; 16]],
) {
    unsafe { _emb_crypto_aes128ecb_encrypt_block(ctx, blocks) }
}
```

Because the trait methods are annotated with `#[export_name = "_emb_crypto_aes128ecb_init"]`
etc., the linker resolves the `extern "Rust"` calls to the actual implementation.

### 3. Use the trait (consumer crate)

In your application or middleware crate, call the free functions generated by the macro:

```rust
use embassy_crypto_driver::{aes128ecb_init, aes128ecb_encrypt_block};

let ctx = aes128ecb_init(&key);
aes128ecb_encrypt_block(&ctx, &mut blocks);
```

These free functions are generated in the trait-defining crate by the `unitrait!` macro.
They have the same signatures as the trait methods but are not generic — they call the
linker-resolved symbols directly.

## `#[opaque]` — opaque context types

When a trait needs an opaque context (key schedule, chaining state, etc.), use
`#[opaque(size = N, align = M)]` on the associated type:

```rust
#[opaque(size = 48, align = 16)]
pub type Context;
```

The macro generates:

```rust
#[repr(C, align(16))]
pub struct Aes128CbcContext {
    _data: [u8; 48],
}
```

This type is `Copy`, `Clone`, and has `as_bytes()` / `as_bytes_mut()` methods. It is
also wrapped in `UnsafeCell` internally so that `&mut Context` methods work correctly
when the context is stored in a `static` or passed across FFI boundaries.

**Important:** The `size` must be large enough to hold whatever the driver implementation
stores in its `Context` type. If the driver's `Context` is larger than the opaque size,
compilation will fail with a size mismatch. The trait author should pick a size that
accommodates all known implementations (e.g. 32 bytes for AES-128 key schedule, 64 bytes
for AES-256 + IV).

## `#[symbol]` — symbol naming convention

Every method and the context type must have a `#[symbol = "..."]` attribute. This
becomes the `#[export_name]` and `extern "Rust"` symbol name. Use a consistent prefix
to avoid collisions:

```
_emb_crypto_aes128ecb_init
_emb_crypto_aes128ecb_encrypt_block
_emb_crypto_aes128gcm_encrypt
_emb_crypto_aes128ccm_context
```

## Generated macro invocation

The `macro NAME_impl(path = $crate);` line inside `unitrait!` defines the name of the
macro that driver crates must call. The `path = $crate` part ensures the macro resolves
types relative to the trait-defining crate.

Driver crates invoke it as:

```rust
crate_name::macro_name!(DriverType);
```

For example:

```rust
embassy_crypto_driver::embassy_crypto_aes128ecb_impl!(AesDriver);
```

## Limitations

- **No default methods** — `unitrait!` does not support trait default implementations.
  Every method must be implemented by the driver.
- **No associated constants** — Only associated types and methods are supported.
- **One implementation per binary** — Because dispatch is via global symbols, you can
  only link one implementation of each unitrait into a single binary. This is by design
  for embedded systems with a single hardware peripheral.
- **`unsafe` under the hood** — The generated wrappers use `unsafe` to call `extern "Rust"`
  functions. This is safe in practice because the symbols are guaranteed to exist by the
  linker (if the driver crate is linked), but the compiler cannot verify it.

## Example: complete unitrait definition

```rust
unitrait::unitrait! {
    /// Hardware-accelerated SHA-256.
    pub trait Sha256 {
        #[opaque(size = 128, align = 8)]
        #[symbol = "_emb_crypto_sha256_context"]
        pub type Context;

        #[symbol = "_emb_crypto_sha256_init"]
        pub fn sha256_init() -> Self::Context;

        #[symbol = "_emb_crypto_sha256_update"]
        pub fn sha256_update(ctx: &mut Self::Context, data: &[u8]);

        #[symbol = "_emb_crypto_sha256_finish"]
        pub fn sha256_finish(ctx: &mut Self::Context, out: &mut [u8; 32]);
    }

    macro embassy_crypto_sha256_impl(path = $crate);
}
```
